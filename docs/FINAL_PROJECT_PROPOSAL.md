# Proposed PBL submission: RiskGate ANPR

**Archive note:** The build and evaluation have now run. For actual measured results and limits, use [EVALUATION_REPORT.md](EVALUATION_REPORT.md). This document records the original plan.

**Deadline:** 16 November 2026  
**One-sentence claim:** A local Indian number plate reader that detects plates, reads them, and chooses when its prediction is safe enough to accept or should be sent for review, with measured accuracy, coverage, and uncertainty.

## Why this is a substantial step beyond the first prototype

The first prototype sent test photos to Gemini and displayed its answer. The final project should work **offline** on full vehicle photos, include a trained local detector, compare at least two local OCR readers, use a measured confidence model, and show the tradeoff between automatic acceptance and mistakes. Gemini can be an optional, cached experiment on a small fixed subset. It must not be required for the demo or the headline result.

The contribution is **selective prediction for Indian ANPR**, not a claim to have invented a new OCR architecture. Good evidence will be the held-out test protocol, honest error bars, and failure examples. A live demo without these results would still look like the old prototype.

## System to build

1. **Detect:** fine-tune one lightweight YOLO detector on the real bounding boxes using the RTX 4060 (8 GB). Report detector precision, recall, and mAP on held-out groups. Keep cropped-plate input as a fallback in the demo.
2. **Read:** run the existing EasyOCR reader as a baseline and test one stronger local reader, such as [FastPlateOCR](https://ankandrew.github.io/fast-plate-ocr/latest/) or PaddleOCR. Select the reader on validation data, then freeze it. Report exact plate match, character error rate (CER), and latency. Evaluate single-row and two-row plates separately where labels permit.
3. **Estimate correctness:** use the existing logistic model with OCR confidence, grammar class, text length, box count, and crop geometry. Fit it on calibration groups only. Show raw versus calibrated reliability using ECE and a reliability diagram.
4. **Route:** choose accept/review thresholds on separate validation groups. Show coverage versus observed error on the untouched test set, with Wilson intervals. An INVALID grammar result can never be directly accepted. A 5% target is a design objective, **not a guarantee** after searching thresholds.
5. **Review and optional second opinion:** uncertain plates go to human review. If a free Gemini key and quota are available, run a small fixed subset once and replay its cache. Compare its accuracy, latency, and call count with the local pipeline. The final system must remain useful with zero API calls.
6. **Demo:** upload a full vehicle photo, show detector box and crop, local OCR text, calibrated confidence, route, reason, and a correction input. Add an evidence tab with plots, dataset counts, and a small gallery of real successes and failures. Include an offline cropped-plate fallback if the detector misses.

## Evaluation rules that make the result credible

- Review roughly 10% of XML labels (about 170) visually, spread across the three sources. Record corrected/ambiguous counts. Do not use OCR outputs as ground truth.
- Split by **source video** for video frames and by normalized plate identity for repeated vehicles. Check near-duplicates before finalizing the split. Save a seed and manifest. Aim for 50% detector training, 20% calibration, 15% threshold validation, and 15% final test by image count while keeping groups intact.
- The detector must never train on images used for the headline end-to-end test. Freeze OCR configuration and thresholds before opening that test.
- Report both crop-only OCR accuracy and end-to-end full-image accuracy; a missed detection counts as an end-to-end error.
- Put the test sample count beside every percentage. Show 95% intervals for accepted error and exact-match accuracy. If 5% cannot be supported, say so and show the achieved point. For context, even **zero errors in 73 accepted plates** is only just enough for the upper end of a two-sided 95% Wilson interval to fall near 5%.
- Include latency and the number of Gemini calls. Show at least one error analysis by low resolution, row layout, source, and grammar class if those labels can be audited.
- Keep a sealed test: no changing the model or thresholds after reading its result. The current code protects `final_test.json` from accidental overwrite, but the team must follow the protocol too.

| [VehiclePaliGemma (2024)](https://arxiv.org/html/2412.14197v1) | Synthetic data and a carefully labeled real evaluation set can complement each other. | Its 600 synthetic training images and 258 Malaysian test images are not a reason to fine-tune a 3B VLM here. |
| [ICPR low-resolution LPR competition (2026)](https://arxiv.org/html/2604.22506v2) | Exact-match recognition, low-resolution slices, and confidence discrimination matter; multi-frame fusion helps video. | Its “confidence gap” measures separation of correct and wrong scores. | [Indian Licence Plate Dataset in the Wild (2021)](https://arxiv.org/pdf/2111.06054) | Indian plate layouts and perspective make detection and crop quality important. | Its full dataset is not currently public via the authors' repo. |
| [Awiros technical report](https://huggingface.co/Awiros/anpr-ocr/blob/main/TechnicalReport.pdf) and [model card](https://huggingface.co/Awiros/anpr-ocr) | A small domain-specific OCR model and careful data curation can beat a slow API on the authors' validation set. The report describes synthetic data, consensus pseudo-labeling, and unreadable-plate abstention. | Its reported 98.42% is an author-reported internal result. **It used the Saisirishan dataset as seed training data**, so testing Awiros on that Kaggle dataset is not an independent benchmark. ## Compressed order of work with study time protected

Keep the student's project study to **25–30 minutes per day**, plus one short demo rehearsal on 15 November. The heavier jobs are data preparation, model runs, and report assembly; run training unattended when possible. The minimum credible submission is a measured local OCR + accept/review system on real labeled crops. Add the full-image detector if it is ready by 13 November. Do not sacrifice the sealed test, honest failure examples, or a working offline demo to add optional Gemini comparisons.

## Minimum presentation package

1. A working offline demo on a full vehicle image and a cropped plate fallback.
2. A dataset card: sources, license, label audit, counts, and leak-free split.
3. Three tables: detector metrics; OCR baselines; acceptance error/coverage/latency at chosen thresholds.
4. Two plots: reliability and risk–coverage; plus a few honest failure examples.
5. A reproducible run command, frozen model/config files, and a short report explaining where each number came from.

**Defense questions to practice:** Why is raw OCR confidence not a probability of a correct plate? How did you prevent video frames and repeated plates leaking across splits? What does a 5% target mean when your test set is finite? Why can the demo still work if Gemini is unavailable?
